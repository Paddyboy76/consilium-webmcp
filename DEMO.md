## If something behaves differently during recording

| What happens | Honest response |
|---|---|
| `deterministic-fallback` appears | Keep the label visible and use the fallback narration. The browser agent's WebMCP calls and Cloudflare retrieval are real; do not call the fallback spontaneous multi-agent reasoning. |
| Council abstains or returns an error | Do not stage unsupported advice. Use an earlier successful inspected result clearly labelled as previously recorded, or record a shorter honest demonstration of the other working flows. |
| UI looks unchanged after a tool write | Refresh/navigate, wait for D1 state to hydrate, and compare returned IDs. Do not claim an automatic visible update before it occurs. |
| A proposal lands in the wrong area | Stop that take. Resolve the actual Social target ID before staging; do not hide the mismatch or repair it with an unrecorded database edit. |
| Commit tool is absent | Check pending state, refresh, and rediscover. Never invent a successful invocation. |
| Rate limit is reached | Wait for the real window or inspect a stored run. Do not reset or change sessions to evade the limit. |
| Clip is too long | Shorten scrolling, introductions, waits, and architecture narration. Keep the genuine tool call, evidence, unchanged-before-approval state, approval, and visible result. |
