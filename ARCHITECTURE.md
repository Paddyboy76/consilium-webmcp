# Architecture

## Recovery application layer

Consilium WebMCP is a zero-build responsive frontend served by Worker Assets. It reuses the owner’s dense dark monospaced Consilium navigation, exact six-domain grouping, mission focus/progress interaction, CAAR reflection vocabulary, genuine Enso asset/behavior, morning-brief hierarchy, council/library, and transparency architecture. A thin browser client calls the same Worker routes exposed through WebMCP.

Migration `0003_recovery_product.sql` adds session-scoped product state. Additive migration `0004_structured_reflection.sql` adds accepted nightly reflections, relational goal reviews, extracted facts, tomorrow directives, and the morning-brief analysis/recommendation link. Additive migration `0005_exact_life_domains.sql` adds canonical domain codes, active/archive state, and explicit migration metadata. Migration `0006_pass5_journal_commit.sql` adds area/goal-linked journal entries and links approved actions to the Today goal created by their one-use commit. First-request reconciliation maps Health→Physical, Relationships→Social, and Vocation→Vocational; the synthetic writing/essay Learning records move defensibly to Vocational while their legacy area row is archived, not deleted. Missing domains and coherent synthetic linked records are inserted idempotently. No audit/history row is discarded. Consequential council actions continue through the `proposals` → atomic `actions` boundary and now become operational Today state. D1 remains canonical; no browser-only state represents a committed fact.

The human reflection modal and WebMCP `record_evening_reflection` call the same `POST /api/reflections` endpoint and server validator. The endpoint verifies exact CAAR keys, readiness ranges, journal/answer lengths, session ownership, completeness over all active Today goals, and missed-goal details before a batch write. Morning-brief selection consumes those records plus active missions, progress logs, earlier recommendations, and counterevidence; displayed IDs are hydrated canonical IDs, and the deterministic fallback avoids causal claims.

The morning brief is deterministic and inspectable: it selects active missions, then explicitly lets the newest reflection’s adaptation and tomorrow implication change the first priority rationale. It stores both the priority JSON and exact evidence IDs.

The UI always publishes a plain-language catalogue of 13 typed WebMCP contracts. Twelve are registered when browser-agent discovery is available; `commit_proposed_action` is registered with an `AbortController` only while the signed session owns a valid pending proposal. Strict schemas distinguish reads, writes, trace-only consultation, staging, and approval-gated commit. Tool calls reach one Cloudflare Worker with bounded JSON inputs.

D1 is canonical for the synthetic longitudinal history, inferred-pattern evidence links, appointments, source packs, consultations, reports, recommendations, proposals, actions, and audit records. Vectorize is a derived 768-dimension cosine index. Workers AI `@cf/baai/bge-base-en-v1.5` embeds queries; metadata filters separate personal memory from each appointed advisor and pack before canonical D1 hydration.

Retrieved text is untrusted data with no instruction, appointment, tool, secret, citation, or mutation authority. Production uses one bounded, low-temperature, low-reasoning Workers AI `@cf/openai/gpt-oss-20b` JSON-schema call under `workers-ai-json-council-v9-gpt-oss-wrapper-normalized`. Cloudflare hosts this OpenAI open-weight reasoning model inside Workers AI: it needs no separate provider API key, exposes `response_format`, has a 128,000-token context window, and is intended for lower-latency reasoning. Explicit low reasoning effort protects the interactive deadline without weakening the server-owned evidence and validation gates. A bounded normalizer accepts only the documented Workers text, Chat Completions, or Responses wrappers (including a nested Workers text envelope) before the same strict Zod hydration. It is the final interactive evidence interpreter while server code retains all retrieval, evidence ownership, hydration, semantic validation, and deterministic fallback authority. The strict record separates situation, remembered facts, interpretations, conflict, duties, unknowns, rejected inference, three distinct advisor scopes/applications/limits, counterevidence, tensions, synthesis, clinical boundary, no more than one immediate action plus one follow-up, and explicit unapproved status. The model sees advisor-qualified stable evidence slots, never database IDs or hashes; server code hydrates only the slots selected for each claim. Actual personal Vectorize matches are hydrated from canonical D1 records before prompting, and advisor retrieval remains question-sensitive, advisor-distinct best-four personal and best-two appointed passages, and separately scoped. Malformed, unsupported, or scope-violating output fails closed to a labelled deterministic fallback.

No OpenAI SDK, OpenAI API, `OPENAI_API_KEY`, external provider call, or Responses API is used. The OpenAI model weights are invoked only through the existing Cloudflare Workers AI binding. Local tests stub that binding and retain the labelled deterministic fixture; no local verification calls a live model.

The model request retains one call, temperature 0.1, 1,600 output tokens, strict `response_format.type=json_schema`, and a 15,000 ms application timeout, with no retry or cascade. Full object and whole-body JSON-string responses pass through the same strict Zod schema, server-owned slot hydration, advisor-scope, and evidence-lane validation; prose and brace extraction are rejected. Schema failures expose only up to eight Zod issue paths/codes, or the fixed `response_body`/`invalid_json` marker for whole-body parse failure. These safe fields accompany model/config/mode/reason/elapsed time in the response and audit; prompts, generated prose, values, validator messages, and arbitrary exception text are excluded. No migration or Vectorize reindex is required because storage, embeddings, dimensions, pipeline hash, and retrieval are unchanged.

Public-demo ownership uses a signed, expiring, versioned `HttpOnly; Secure; SameSite=Strict` cookie. It isolates consultations, traces, proposals, commits, resets, and audit records; it is not general user authentication.

Deployment: browser/WebMCP → isolated Cloudflare Worker → D1 + Workers AI + Vectorize. No Debian application service is part of the live architecture.
