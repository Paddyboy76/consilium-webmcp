# Judge review

## What to evaluate

| Criterion | Concrete evidence |
|---|---|
| WebMCP leverage | Seven stable semantic tools, a state-dependent eighth commit tool, signed-session state, and a UI that changes from the same tool results |
| Execution | Public HTTPS app; canonical D1 memory/source data; Workers AI + filtered Vectorize retrieval; deterministic reports, validation, abstention, and atomic commit |
| Potential impact | Advice incorporates a durable history of attempts, failures, adaptations, outcomes, counterevidence, confidence, and provenance instead of reconstructing the person per chat |
| Creativity & ambition | A user's chosen browser agent collaborates with a user-appointed council while a changing capability boundary keeps persistence under human control |

## Skeptical review

- **“The agents are fake.”** The live council is deterministic, and the UI, health endpoint, submission copy, and evidence say so. The inactive Agents SDK adapter is not presented as execution proof.
- **“Citations are cosmetic.”** Every accepted personalized claim must resolve to canonical D1 records from both personal memory and the active appointed source pack. Unknown, cross-pack, low-score, or unsupported citations cause rejection or abstention.
- **“Memory is decorative.”** The decision path retrieves personal outcomes before advice; patterns include support and counterevidence; focused tests prove relevant history changes advice while unrelated history does not.
- **“WebMCP adds nothing.”** The external agent receives a stable typed collaboration boundary and a one-use capability that appears only after a human-reviewable proposal exists.
- **“Actions bypass control.”** Consultation reports `persistent_mutation: false`; proposal creation leaves actions unchanged; only a session owner can explicitly commit once; replay is rejected.
- **“The demo is staged.”** The data is openly labelled synthetic, but every demonstrated tool call uses the live Worker paths. Server-live acceptance verifies D1, Workers AI, Vectorize, session isolation, mutation, audit, replay rejection, and cleanup.

## Honest evidence boundary

Browser/WebMCP proof covers exact five-result memory retrieval, three validated appointed councillors, canonical dual grounding, a non-abstained decision, and visible trace/guardrail state. The full mutation lifecycle is server-live proven but not yet browser-proven. OpenAI application execution is neither configured nor claimed.
